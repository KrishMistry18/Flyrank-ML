# FL-08: Dynamic Portfolio Feature (Ask Krish AI)

### What I built
Ask Krish AI is the single dynamic feature of my portfolio. Instead of just reading a static list of my projects, recruiters and hiring managers can chat with an interactive assistant that knows everything about my technical background, skills, and experience.

### What the backend is
The backend is a single, serverless API route (`/api/chat`) hosted on Vercel. It is written in Node.js. When a user asks a question, this backend acts as the secure middleman between the visitor and the AI model (Gemini). It takes the user's question, attaches my strict system instructions and personal knowledge base, and forwards it to the AI.

### How the data flows
The entire process happens in milliseconds:
1. **Visitor** types a question into the Ask Krish AI UI.
2. **Ask Krish AI UI** sends a POST request with the message to my `/api/chat` backend.
3. **API** receives the request and loads my local JSON **portfolio knowledge** file (containing my verified resume data).
4. **AI/fallback logic** determines how to handle it. The backend combines the user's message with the knowledge base and a strict system prompt, then sends it to the Gemini API using a hidden server-side key. (If the API key were missing, it would automatically fall back to a hardcoded keyword mock).
5. **Response** is generated by the AI, sent back to my API, and forwarded to the frontend.
6. **UI** displays the generated answer to the visitor.

### Why I chose it
An interactive portfolio agent demonstrates my ability to turn a static portfolio into a usable tool. It shows I can build full-stack applications, handle API integrations securely, and design useful AI features with proper guardrails. It's much more engaging than a simple contact form.

### Free-tier hosting
This entire feature operates on a 100% free tier. The portfolio frontend and the serverless backend are hosted on Vercel's free Hobby tier. The AI responses are generated using the Google Gemini free tier API. There are no paid servers running.

### Security
Security is a top priority. My Gemini API key is never exposed to the visitor. It is stored securely as an Environment Variable in my Vercel dashboard (`GEMINI_API_KEY`). The visitor's browser only ever talks to my Vercel backend, and my backend is the only thing that talks to Gemini. This prevents anyone from stealing my key or abusing my API quota.

### Limitations
Because this relies on a free-tier architecture, there are a few limitations:
- **Dependency on the AI API:** If the Gemini API goes down or I hit my free-tier rate limit, the agent relies on a basic keyword-matching fallback system.
- **Context Limitations:** The agent uses "Context Stuffing" (loading the entire JSON into the prompt) rather than a complex Vector Database. This is fast and cheap, but it limits how much data I can provide the agent before it gets overwhelmed or exceeds token limits.
- **Strict Guardrails:** To prevent hallucinations, the agent is strictly instructed to say "I don't have that information" for anything not explicitly in the knowledge base. It won't engage in general chit-chat.
